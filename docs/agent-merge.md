## Слияние работы других подпесочниц

Ты работаешь в песочнице проекта. Имена в коде заменены нейтральными
плейсхолдерами — не пытайся угадать или восстановить настоящие. Всё, что ты
сохраняешь в этой папке, автоматически уходит в основной проект, в git-ветку
этой песочницы. Своего git-репозитория у песочницы нет.

Когда тебя просят слить работу других веток (подпесочниц), материал уже
подготовлен в папке `.anonymus-merge/`:

- `index.txt` — список патчей и сколько файлов в каждом изменено, добавлено и удалено;
- `<ветка>.patch` — изменения этой ветки относительно общей основы, в формате
  `git diff`. Каждый кусок записан в той же кодировке и с теми же концами строк,
  что и файл в этой песочнице, поэтому патчи применяются как есть.

### Порядок работы

1. **Не меняй `.anonymus-merge/`** и не переноси её содержимое в код. Это
   служебная папка, она не синхронизируется.

2. **Сливай во временной копии, а не прямо в песочнице.** Иначе в проект
   уйдёт незавершённое состояние и служебные файлы `*.rej` / `*.orig`.
   ```bash
   SB="$(pwd)"                       # корень песочницы
   W="$(mktemp -d)"                  # вне песочницы
   cp -a "$SB/." "$W/" && rm -rf "$W/.anonymus-merge"
   cd "$W"
   git rev-parse 2>/dev/null && echo "СТОП: копия внутри git-репозитория"
   ```
   Временная папка не должна оказаться внутри какого-либо git-репозитория:
   иначе `git apply` будет считать пути от его корня.

3. **Применяй патчи по одному**, в порядке `index.txt`:
   ```bash
   git apply --reject --whitespace=nowarn "$SB/.anonymus-merge/<ветка>.patch"
   ```
   Всё, что применилось, уже на месте. Кусок, который не удалось применить,
   сохраняется рядом с файлом как `<файл>.rej` — это настоящее пересечение веток.

4. **Разреши каждый `*.rej` вручную:**
   - сохрани смысл **обеих** сторон: например, обе добавленные строки, оба
     `#include`, обе новые функции. Порядок выбирай так, чтобы код оставался
     корректным (сначала инициализация, потом использование);
   - если правки по сути противоречат друг другу, выбери вариант, который не
     ломает поведение, и обязательно опиши это в отчёте;
   - **не меняй кодировку и концы строк файлов.** В проекте бывают файлы в
     Windows-1251 и с CRLF: правь их так, чтобы они такими и остались;
   - после разрешения удали `*.rej` и `*.orig`.

5. **Проверь итог:**
   ```bash
   find . -name "*.rej" -o -name "*.orig"          # должно быть пусто
   grep -rn "^<<<<<<<\|^>>>>>>>" . || true          # маркеров конфликта нет
   ```
   Затем собери проект и прогони тесты так же, как обычно в этом проекте.

6. **Перенеси результат в песочницу** — одной командой, когда всё готово.
   Удалённые патчами файлы удалятся и в песочнице, служебная папка не трогается:
   ```bash
   rsync -a --delete --exclude .anonymus-merge "$W/" "$SB/"
   ```
   Если `rsync` нет, скопируй изменённые и новые файлы (`cp -a "$W/." "$SB/"`)
   и вручную удали в `$SB` файлы, которые патчи удаляют (`deleted file` в патче).

7. **Не коммить.** В песочнице нет git проекта. Итог зафиксирует пользователь.

8. **Напиши отчёт:**
   - какие патчи применены;
   - какие были пересечения и как ты их разрешил;
   - что собрал и проверил;
   - что осталось под вопросом.

Если пользователь пересоздал патчи (утилита делает это заново по запросу),
начни с шага 2 на свежей копии песочницы.
