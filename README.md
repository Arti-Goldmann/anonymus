# anonymus

Консольная утилита, которая **автоматически** синхронизирует основной проект и
песочницу ИИ-агентов, заменяя реальные имена на плейсхолдеры по пути в песочницу и
возвращая их обратно по пути в проект. Пока утилита запущена:

- изменили файл в песочнице → он появляется в проекте с реальными именами;
- изменили файл в проекте → он появляется в песочнице с плейсхолдерами;
- удалили файл на одной стороне → он удаляется на другой, а копия ложится в `.anonymus/trash/`;
- изменили один файл с обеих сторон → правки сливаются автоматически, а если это
  невозможно, файл ждёт вашего решения (взять одну из версий или слить в VS Code).

Замены работают и в содержимом, и в путях: `BIGcorpProject_cpu01/main.c` ⇄
`MyProject_cpu01/main.c`. Кодировки (UTF-8 / win1251), BOM и концы строк
(LF / CRLF) каждого файла сохраняются.

## Установка

Нужен Node.js 20+.

```powershell
cd D:\DATA\Documents\GitRep\MyRep\software\PC\anonymus
npm install
npm install -g .
```

После этого команда `anonymus` доступна в любой папке. Чтобы обновить утилиту
после изменения кода, достаточно `npm run build` — глобальная команда ссылается на
эту папку.

## Быстрый старт

```powershell
cd D:\путь\к\основному\проекту
anonymus init      # создаёт anonymus.yaml и добавляет его и .anonymus/ в .gitignore
notepad anonymus.yaml
anonymus           # скан → сверка → живая синхронизация
```

При запуске утилита сравнивает обе стороны с учётом замен. Если они расходятся,
предлагает:

| Вариант | Что происходит |
|---|---|
| 1. Проект → песочница | песочница становится копией проекта (пустая песочница заполняется) |
| 2. Песочница → проект | проект становится копией песочницы |
| 3. Умная сверка | свежие изменения переносятся в нужную сторону, правки с двух сторон сливаются, неоднозначное откладывается для вас |
| 4. Разобрать по файлам | все различия попадают в список решений |

Перед применением показывается, сколько файлов будет перенесено и **удалено**.
Всё перезаписываемое и удаляемое сохраняется в `.anonymus/trash/<время>/`.

## Клавиши

| Клавиша | Действие |
|---|---|
| `c` | список файлов, ждущих решения |
| `p` | пауза / продолжить (изменения копятся и обрабатываются после) |
| `r` | пересканировать обе стороны |
| `o` | открыть папку корзины |
| `q`, `Ctrl-C` | остановиться (состояние сохраняется) |

Рамка статуса вверху показывает состояние синхронизации:

- оранжевая «● синхронизация активна» — всё синхронно;
- красная «! N файл(ов) ждёт решения» — есть конфликты, нажмите `c`;
- жёлтая «⏸ пауза» — синхронизация приостановлена.

Справа в рамке счётчики за сессию: сколько файлов перенесено в песочницу, в
проект и сколько удалено.

В списке конфликтов: `p` — оставить версию проекта, `s` — версию песочницы,
`m` — открыть трёхсторонний merge editor VS Code. Слияние идёт с реальными именами;
после сохранения результата и закрытия вкладки он записывается в обе стороны.

## Конфиг `anonymus.yaml`

Полный пример с комментариями — в [anonymus.example.yaml](anonymus.example.yaml).

```yaml
sandbox: ../sandbox1          # путь к песочнице (не внутри проекта)

sync:
  include: ["**"]             # ЯВНО: что синхронизировать ("**" — всё)
  exclude:                    # что нельзя (синтаксис .gitignore)
    - .venv*                  # .venv, .venv-ubuntu, .venv2 ... на любой глубине
    - .cache                  # только имя ровно .cache (.cache-old не затронет)
    - /build                  # только build/ в корне (src/build не затронет)
    - src/gen/tmp.c           # строго этот файл
  binary: ["*.bin"]           # дополнительно к стандартным бинарным типам
  encoding: auto              # auto | utf8 | win1251
  sandbox_encoding: keep      # keep | utf8 — в песочнице всегда UTF-8
  poll: false                 # true, если изменения из Docker не замечаются
  debounce_ms: 300

replacements:
  - real: "BIGcorpProject"
    placeholder: "MyProject"
    variants: auto            # + camelCase / snake_case / UPPER_CASE варианты
  - real: "romashka.ru"
    placeholder: "example.com"
    variants: exact
```

Шаблоны `include` / `exclude` проверяются по **реальному** пути файла в проекте,
поэтому их пишут с реальными именами, даже для файлов, созданных в песочнице.

### Варианты регистра

Для `variants: auto` из `BIGcorpProject → MyProject` получаются, например,
`bigcorp_project → my_project`, `BIGCORP_PROJECT → MY_PROJECT`,
`bigcorpProject → myProject`, `bigcorp-project → my-project`. Если после
анонимизации в тексте всё равно встречается реальное имя (в любом написании,
например `Bigcorp Project`), в ленте появится «⚠ возможная утечка». Значит, стоит
добавить замену для этого написания.

## Служебные файлы

Всё служебное хранится в **проекте**, в `.anonymus/`; в песочницу утилита ничего
своего не пишет:

- `profiles/default/state.json` — как выглядели обе стороны при последней синхронизации;
- `profiles/default/base/` — снимки для трёхстороннего слияния;
- `trash/` — резервные копии удалённых и перезаписанных файлов;
- `merge/` — временные файлы слияния в VS Code.

## Другие команды

```powershell
anonymus scan                            # только отчёт о расхождениях (код 1, если они есть)
anonymus --no-tui --strategy smart       # построчный лог без интерфейса
anonymus -c D:\proj\anonymus.yaml        # конфиг не из текущей папки
```

## Песочница в Docker

Если песочница смонтирована в контейнер (`sandbox.ps1` из transfer tool), правки
агента внутри контейнера попадают на диск Windows, и утилита видит их как обычно.
Если какие-то изменения не замечаются, включите `sync.poll: true`.

## Ограничения

Утилита снижает риск утечки, но не гарантирует полную анонимизацию: таблицу замен
нужно поддерживать, а предупреждения об утечках — проверять. Она не заменяет
разрешения заказчика на работу с кодом.

## В планах: ветки и несколько песочниц

Для каждой ветки проекта будет своя песочница, чтобы несколько агентов работали
параллельно, а утилита переключала активную песочницу вместе с веткой проекта
(аналог `git worktree` с анонимизацией). Состояние уже хранится по профилям
(`.anonymus/profiles/<имя>/`), так что новые профили добавятся без миграции.
