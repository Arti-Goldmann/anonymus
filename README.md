# anonymus

Консольная утилита, которая **автоматически** синхронизирует проект и песочницы
ИИ-агентов, заменяя реальные имена на плейсхолдеры по пути в песочницу и
возвращая их обратно по пути в проект. Пока утилита запущена:

- изменили файл в песочнице → он появляется в проекте с реальными именами;
- изменили файл в проекте → он появляется в песочнице с плейсхолдерами;
- удалили файл на одной стороне → он удаляется на другой, а копия ложится в `.anonymus/trash/`;
- изменили один файл с обеих сторон → правки сливаются автоматически, а если это
  невозможно, файл ждёт вашего решения (взять одну из версий или слить в VS Code).

Замены работают и в содержимом, и в путях: `BIGcorpProject_cpu01/main.c` ⇄
`MyProject_cpu01/main.c`. Кодировки (UTF-8 / win1251), BOM и концы строк
(LF / CRLF) каждого файла сохраняются.

В git-проекте у каждой песочницы своя ветка и свой **git worktree** проекта, и все
пары синхронизируются одновременно: несколько агентов работают параллельно, а вы
видите работу каждого в VS Code отдельно.

## Установка

Нужен Node.js 20+.

```powershell
cd D:\DATA\Documents\GitRep\MyRep\software\PC\anonymus
npm install
npm install -g .
```

После этого команда `anonymus` доступна в любой папке. Чтобы обновить утилиту
после изменения кода, достаточно `npm run build` — глобальная команда ссылается на
эту папку.

## Быстрый старт

```powershell
cd D:\work\proj
anonymus init      # создаёт anonymus.yaml и добавляет его и .anonymus/ в .gitignore
notepad anonymus.yaml
anonymus           # n — создать первую подпесочницу
```

## Как устроено

```
D:\work\proj                      основной проект — ваш, anonymus его не синхронизирует
D:\work\proj.worktrees\feature-1  git worktree ветки feature-1  ⇄  D:\work\sandboxes\feature-1
D:\work\proj.worktrees\feature-2  git worktree ветки feature-2  ⇄  D:\work\sandboxes\feature-2
```

- **Подпесочница** — это пара «git worktree проекта ⇄ папка песочницы». Worktree —
  вторая рабочая копия того же репозитория: история и ветки общие, а выбранная
  ветка и незакоммиченные файлы — свои.
- Все пары синхронизируются **одновременно**, переключать ничего не нужно.
- **Основная папка проекта не синхронизируется**: переключайте в ней ветки,
  собирайте, сливайте — песочниц это не касается.
- Worktree лежат рядом с проектом (`worktrees_dir`, по умолчанию
  `<проект>.worktrees`), а не внутри: иначе сборка и поиск в проекте видели бы
  каждый файл по нескольку раз.
- Имя папки песочницы анонимизируется: для ветки `BIGcorpProject-uart` песочница
  будет `MyProject-uart`, и реальное имя не попадёт в путь, который видит агент.
  Папка worktree — на вашей стороне, в ней реальные имена.

Проект без git работает как раньше: одна пара «папка проекта ⇄ `sandbox:`».

В worktree есть только то, что закоммичено в ветку: незакоммиченные и
игнорируемые git файлы основной папки в подпесочницу не попадут. **Подмодули**
anonymus при создании подпесочницы ставит сам: каждый копируется из основной
папки проекта, если там есть нужная версия (быстро, без сети; получается
независимый клон с тем же удалённым репозиторием), иначе скачивается по сети.
Если не удалось ни так, ни так, подпесочница всё равно создаётся, а в журнале
появляется команда для повторной попытки. Правки
агента внутри подмодуля коммитятся в самом подмодуле — `k` и `m` работают с
основным репозиторием.

### Как смотреть, что сделал агент

Работа агента — это незакоммиченные изменения в его worktree. В VS Code:

- Source Control основной папки показывает и её worktree (в свежих версиях VS Code);
- или откройте общую родительскую папку (`D:\work`) и поставьте
  `"git.repositoryScanMaxDepth": 2` — каждый worktree будет отдельным
  репозиторием со своим списком изменений и diff.

Из терминала: `git -C ..\proj.worktrees\feature-1 diff`, или из основной папки
после коммита — `git diff master..feature-1`.

## Экран

Главный экран — список подпесочниц, под ним общий журнал (у каждой строки —
`[подпесочница]`). У каждой пары свой статус:

| Значок | Что значит |
|---|---|
| `●` синхронно | всё совпадает |
| `!` N ждут решения | конфликты, нажмите `c` |
| `?` ждёт сверки | проект и песочница расходятся — `Enter`, выбрать, как свести |
| `⇄` слияние | идёт git merge, ждёт разрешения конфликтов |
| `⏸` пауза | синхронизация пары приостановлена |
| `✖` остановлена | синхронизировать небезопасно — `Enter`, см. «Защита» |

Справа — счётчики за сессию: `→` в песочницу, `←` в проект, `✕` удалено.

Вкладка терминала получает заголовок `🎭 anonymus · <проект>`. VS Code по
умолчанию показывает на вкладке имя процесса; чтобы видеть заголовок, добавьте
в настройки `"terminal.integrated.tabs.title": "${sequence}"`.

## Клавиши

| Клавиша | Действие |
|---|---|
| `↑` `↓` | выбрать подпесочницу |
| колесо мыши, `PgUp` `PgDn` | листать историю журнала (новые строки не сдвигают то, что вы читаете) |
| `Enter` | открыть то, что ей нужно: сверку, конфликты или её проблему |
| `n` | новая: имя → ветка (новая от выбранной `Tab`-ом или существующая), её worktree и песочница; песочница сразу заполняется |
| `d` | удалить: песочница — в корзину, worktree — `git worktree remove`, ветка остаётся |
| `m` | слить сюда работу других подпесочниц (см. «Слияние») |
| `k` | закоммитить незакоммиченное в worktree; во время слияния — продолжить его |
| `a` | прервать слияние |
| `c` | файлы, ждущие решения |
| `p` | пауза / продолжить для выбранной пары |
| `r` | пересканировать обе стороны |
| `o` | открыть папку корзины |
| `q`, `Ctrl-C` | остановиться (состояние сохраняется) |

Чтобы колесо листало журнал, а не работало как стрелки, утилита включает в
терминале отчёт о мыши. Выделять текст мышью тогда можно с зажатым `Shift`.

В списке конфликтов: `p` — оставить версию проекта, `s` — версию песочницы,
`m` — открыть трёхсторонний merge editor VS Code. Слияние идёт с реальными именами;
после сохранения результата и закрытия вкладки он записывается в обе стороны.

## Сверка при запуске

При запуске каждая пара сравнивается с учётом замен. Однозначные случаи
применяются сами: пустая песочница заполняется, односторонние изменения
переносятся. Если есть удаления или правки с двух сторон, пара ждёт решения:

| Вариант | Что происходит |
|---|---|
| 1. Проект → песочница | песочница становится копией worktree |
| 2. Песочница → проект | worktree становится копией песочницы |
| 3. Умная сверка | свежие изменения переносятся в нужную сторону, правки с двух сторон сливаются, неоднозначное откладывается |
| 4. Разобрать по файлам | все различия попадают в список решений |

Всё перезаписываемое и удаляемое сохраняется в `.anonymus/trash/<время>/<подпесочница>/`.

## Защита

Главное правило: **песочница синхронизируется только со своим worktree.** Если
worktree удалили или пересоздали через git, подменили папку или переключили в
нём ветку, синхронизация пары останавливается раньше, чем что-то перенесётся.
Остальные пары продолжают работать.

Как это проверяется: при создании worktree anonymus кладёт метку с случайным id в
его собственную служебную папку git (`.git/worktrees/<имя>/anonymus.json`). Git
удаляет эту папку вместе с worktree, поэтому worktree, созданный заново на том же
месте, метки не имеет и за «свой» не принимается. Проверка идёт при запуске,
каждую секунду и перед каждым переносимым файлом.

| Что случилось | Что видно | Что делать (`Enter` на паре) |
|---|---|---|
| worktree удалён (`git worktree remove`, вручную) | ✖ worktree удалён | `w` — пересоздать из ветки; `u` — если его переместили `git worktree move` |
| на месте worktree обычная папка или клон | ✖ не worktree | `w` — пересоздать (содержимое папки уйдёт в корзину) |
| worktree пересоздан через git | ✖ чужой worktree | `l` — привязать, если это правильный; `w` — пересоздать |
| в worktree выбрана другая ветка | ✖ в worktree ветка … | `x` — вернуть ветку |
| пропала папка песочницы | ✖ песочница пропала | `f` — создать заново и заполнить из worktree |
| разом исчезло много файлов с одной стороны | ✖ массовое удаление | `Enter` — сверка: вернуть файлы или подтвердить удаление |

После `w` и `l` история синхронизации пары сбрасывается, и автоматической сверки
не будет: незакоммиченная работа worktree могла пропасть, а в песочнице она
есть. На экране сверки рекомендуется «Песочница → проект» — это вернёт работу
агента в worktree.

Ещё при запуске проверяется, что у двух подпесочниц нет общего worktree, общей
песочницы или общей ветки и что песочницы не лежат внутри worktree или проекта.

## Слияние работы нескольких агентов

Сливает настоящий `git merge` в worktree подпесочницы-цели. Агент нужен только
для конфликтов.

1. **В начале работы** создайте цель и от неё ветки агентов:
   - `n` → `result-merge` → основа `master` (`Tab`) → `Enter`;
   - `n` → `agent-a` → основа `result-merge` → `Enter`, так же `agent-b`, `agent-c`.
2. **Агенты работают** в своих песочницах.
3. **Слияние.** Встаньте на `result-merge` и нажмите `m`. Ветки, созданные от неё,
   уже отмечены (пробел — изменить), `Enter`. По очереди для каждой ветки:
   - её незакоммиченная работа коммитится («anonymus: работа agent-a»);
   - в worktree `result-merge` выполняется `git merge --no-ff agent-a`;
   - без пересечений git сливает сам, результат синхронизацией уходит в песочницу
     `result-merge`, и дальше следующая ветка.
4. **Конфликт.** anonymus останавливается (`⇄ слияние agent-c: конфликты`).
   Файлы с маркерами `<<<<<<< ======= >>>>>>>` синхронизация отдаёт в песочницу
   `result-merge` — анонимизированными. В `.anonymus-merge/` этой песочницы:
   - `CONFLICTS.txt` — какие файлы разрешить и как;
   - `agent-c.patch` — что вообще меняла эта ветка от общей основы, чтобы понять её намерение.

   Скажите агенту в `result-merge`: «разреши конфликты слияния по
   `.anonymus-merge/CONFLICTS.txt`, собери и проверь». Инструкция для его
   `CLAUDE.md` — [docs/agent-merge.md](docs/agent-merge.md). Можно разрешить и
   самому в VS Code: файлы с маркерами лежат и в worktree.
5. **Продолжить** — `k`: anonymus проверяет, что маркеров не осталось и всё
   синхронизировано, коммитит слияние и переходит к следующей ветке. `a` —
   прервать (`git merge --abort`).
6. **В master** — в основной папке проекта:
   ```powershell
   git merge --squash result-merge
   git commit -m "Слияние: agent-a, agent-b, agent-c"
   ```

Если агенты поработали ещё, повторное `m` сольёт только новое.

## Конфиг `anonymus.yaml`

Полный пример с комментариями — в [anonymus.example.yaml](anonymus.example.yaml).

```yaml
sandboxes_dir: ../sandboxes   # где создавать песочницы (не внутри проекта)
# worktrees_dir: ../proj.worktrees   # где их worktree; по умолчанию <проект>.worktrees
# sandbox: ../sandbox1        # только для проекта без git

sync:
  include: ["**"]             # ЯВНО: что синхронизировать ("**" — всё)
  exclude:                    # что нельзя (синтаксис .gitignore)
    - .venv*                  # .venv, .venv-ubuntu, .venv2 ... на любой глубине
    - .cache                  # только имя ровно .cache (.cache-old не затронет)
    - /build                  # только build/ в корне (src/build не затронет)
    - src/gen/tmp.c           # строго этот файл
  binary: ["*.bin"]           # дополнительно к стандартным бинарным типам
  encoding: auto              # auto | utf8 | win1251
  sandbox_encoding: keep      # keep | utf8 — в песочнице всегда UTF-8
  poll: false                 # true, если изменения из Docker не замечаются
  debounce_ms: 300

replacements:
  - real: "BIGcorpProject"
    placeholder: "MyProject"
    variants: auto            # + camelCase / snake_case / UPPER_CASE варианты
  - real: "romashka.ru"
    placeholder: "example.com"
    variants: exact
```

Шаблоны `include` / `exclude` проверяются по **реальному** пути файла в проекте,
поэтому их пишут с реальными именами, даже для файлов, созданных в песочнице.
Служебный файл `.git` worktree не синхронизируется никогда.

### Варианты регистра

Для `variants: auto` из `BIGcorpProject → MyProject` получаются, например,
`bigcorp_project → my_project`, `BIGCORP_PROJECT → MY_PROJECT`,
`bigcorpProject → myProject`, `bigcorp-project → my-project`. Если после
анонимизации в тексте всё равно встречается реальное имя (в любом написании,
например `Bigcorp Project`), в журнале появится «⚠ возможная утечка». Значит, стоит
добавить замену для этого написания.

## Служебные файлы

Всё служебное хранится в **основном проекте**, в `.anonymus/`; в worktree и
песочницы утилита своего не пишет (кроме метки в служебной папке git worktree и
`.anonymus-merge/` в песочнице цели во время слияния):

- `sandboxes.json` — подпесочницы: ветки, worktree, песочницы, идущие слияния;
- `profiles/<подпесочница>/state.json` — как выглядели обе стороны при последней синхронизации;
- `profiles/<подпесочница>/base/` — снимки для трёхстороннего слияния;
- `anonymus.log` — журнал событий всех подпесочниц;
- `trash/` — резервные копии удалённых и перезаписанных файлов;
- `merge/` — временные файлы слияния в VS Code.

`sandboxes.json` старого формата (переключение веток через stash) не
поддерживается: удалите его и создайте подпесочницы заново.

## Другие команды

```powershell
anonymus scan                              # только отчёт о расхождениях (код 1, если они есть)
anonymus check "ООО МИП \"Ромашка\""       # как строка будет выглядеть в песочнице и какие правила сработали
anonymus check --file src\main.c         # то же для файла: изменённые строки, кодировка, утечки
anonymus --no-tui --strategy smart         # построчный лог без интерфейса, все пары
anonymus -c D:\proj\anonymus.yaml          # конфиг не из текущей папки
anonymus sandboxes                         # подпесочницы и их состояние
anonymus sandbox new <имя> [--from <ветка>]
anonymus sandbox remove <имя> [--force]    # --force — даже с незакоммиченным в worktree
anonymus merge result-merge                # источники по умолчанию — ветки от result-merge
anonymus merge --continue result-merge
anonymus merge --abort result-merge
anonymus commit <имя> [-m "сообщение"]
```

## Агенты в Docker

Агенты работают в контейнере, а anonymus — на Windows. Положите `.devcontainer`
(Dockerfile + devcontainer.json) в папку `sandboxes_dir`, откройте эту папку в
VS Code и выполните **Dev Containers: Reopen in Container**: в контейнер
смонтируются все песочницы — только с плейсхолдерами, без проекта и его worktree.
Сама папка `.devcontainer` лежит рядом с песочницами, а не внутри них, и не
синхронизируется.

Правки агента внутри контейнера попадают на диск Windows, и утилита видит их как
обычно. Если какие-то изменения не замечаются, включите `sync.poll: true`.

На стенде (`npm run demo`) так и сделано: `demo\sandboxes\.devcontainer`
сохраняется при сбросе стенда.

## Ограничения

Утилита снижает риск утечки, но не гарантирует полную анонимизацию: таблицу замен
нужно поддерживать, а предупреждения об утечках — проверять. Она не заменяет
разрешения заказчика на работу с кодом.
