# anonymus

Консольная утилита, которая **автоматически** синхронизирует основной проект и
песочницу ИИ-агентов, заменяя реальные имена на плейсхолдеры по пути в песочницу и
возвращая их обратно по пути в проект. Пока утилита запущена:

- изменили файл в песочнице → он появляется в проекте с реальными именами;
- изменили файл в проекте → он появляется в песочнице с плейсхолдерами;
- удалили файл на одной стороне → он удаляется на другой, а копия ложится в `.anonymus/trash/`;
- изменили один файл с обеих сторон → правки сливаются автоматически, а если это
  невозможно, файл ждёт вашего решения (взять одну из версий или слить в VS Code).

Замены работают и в содержимом, и в путях: `BIGcorpProject_cpu01/main.c` ⇄
`MyProject_cpu01/main.c`. Кодировки (UTF-8 / win1251), BOM и концы строк
(LF / CRLF) каждого файла сохраняются.

## Установка

Нужен Node.js 20+.

```powershell
cd D:\DATA\Documents\GitRep\MyRep\software\PC\anonymus
npm install
npm install -g .
```

После этого команда `anonymus` доступна в любой папке. Чтобы обновить утилиту
после изменения кода, достаточно `npm run build` — глобальная команда ссылается на
эту папку.

## Быстрый старт

```powershell
cd D:\путь\к\основному\проекту
anonymus init      # создаёт anonymus.yaml и добавляет его и .anonymus/ в .gitignore
notepad anonymus.yaml
anonymus           # скан → сверка → живая синхронизация
```

При запуске утилита сравнивает обе стороны с учётом замен. Если они расходятся,
предлагает:

| Вариант | Что происходит |
|---|---|
| 1. Проект → песочница | песочница становится копией проекта (пустая песочница заполняется) |
| 2. Песочница → проект | проект становится копией песочницы |
| 3. Умная сверка | свежие изменения переносятся в нужную сторону, правки с двух сторон сливаются, неоднозначное откладывается для вас |
| 4. Разобрать по файлам | все различия попадают в список решений |

Перед применением показывается, сколько файлов будет перенесено и **удалено**.
Всё перезаписываемое и удаляемое сохраняется в `.anonymus/trash/<время>/`.

## Клавиши

| Клавиша | Действие |
|---|---|
| `c` | список файлов, ждущих решения |
| `b` | подпесочницы и ветки: переключить, создать, удалить |
| `p` | пауза / продолжить (изменения копятся и обрабатываются после) |
| `r` | пересканировать обе стороны |
| `o` | открыть папку корзины |
| `q`, `Ctrl-C` | остановиться (состояние сохраняется) |

Рамка статуса вверху показывает состояние синхронизации:

- оранжевая «● синхронизация активна» — всё синхронно;
- красная «! N файл(ов) ждёт решения» — есть конфликты, нажмите `c`;
- жёлтая «⏸ пауза» — синхронизация приостановлена.

Справа в рамке счётчики за сессию: сколько файлов перенесено в песочницу, в
проект и сколько удалено.

В списке конфликтов: `p` — оставить версию проекта, `s` — версию песочницы,
`m` — открыть трёхсторонний merge editor VS Code. Слияние идёт с реальными именами;
после сохранения результата и закрытия вкладки он записывается в обе стороны.

## Конфиг `anonymus.yaml`

Полный пример с комментариями — в [anonymus.example.yaml](anonymus.example.yaml).

```yaml
sandbox: ../sandbox1          # путь к песочнице (не внутри проекта)

sync:
  include: ["**"]             # ЯВНО: что синхронизировать ("**" — всё)
  exclude:                    # что нельзя (синтаксис .gitignore)
    - .venv*                  # .venv, .venv-ubuntu, .venv2 ... на любой глубине
    - .cache                  # только имя ровно .cache (.cache-old не затронет)
    - /build                  # только build/ в корне (src/build не затронет)
    - src/gen/tmp.c           # строго этот файл
  binary: ["*.bin"]           # дополнительно к стандартным бинарным типам
  encoding: auto              # auto | utf8 | win1251
  sandbox_encoding: keep      # keep | utf8 — в песочнице всегда UTF-8
  poll: false                 # true, если изменения из Docker не замечаются
  debounce_ms: 300

replacements:
  - real: "BIGcorpProject"
    placeholder: "MyProject"
    variants: auto            # + camelCase / snake_case / UPPER_CASE варианты
  - real: "romashka.ru"
    placeholder: "example.com"
    variants: exact
```

Шаблоны `include` / `exclude` проверяются по **реальному** пути файла в проекте,
поэтому их пишут с реальными именами, даже для файлов, созданных в песочнице.

### Варианты регистра

Для `variants: auto` из `BIGcorpProject → MyProject` получаются, например,
`bigcorp_project → my_project`, `BIGCORP_PROJECT → MY_PROJECT`,
`bigcorpProject → myProject`, `bigcorp-project → my-project`. Если после
анонимизации в тексте всё равно встречается реальное имя (в любом написании,
например `Bigcorp Project`), в ленте появится «⚠ возможная утечка». Значит, стоит
добавить замену для этого написания.

## Служебные файлы

Всё служебное хранится в **проекте**, в `.anonymus/`; в песочницу утилита ничего
своего не пишет:

- `sandboxes.json` — подпесочницы, их ветки и какая активна;
- `profiles/<подпесочница>/state.json` — как выглядели обе стороны при последней синхронизации;
- `profiles/<подпесочница>/base/` — снимки для трёхстороннего слияния;
- `anonymus.log` — журнал событий всех подпесочниц;
- `trash/` — резервные копии удалённых и перезаписанных файлов;
- `merge/` — временные файлы слияния в VS Code.

## Другие команды

```powershell
anonymus scan                            # только отчёт о расхождениях (код 1, если они есть)
anonymus --no-tui --strategy smart       # построчный лог без интерфейса
anonymus -c D:\proj\anonymus.yaml        # конфиг не из текущей папки
anonymus sandboxes                       # список подпесочниц
anonymus sandbox new <имя>               # новая ветка от текущей + подпесочница
anonymus sandbox switch <имя>            # переключить проект на ветку подпесочницы
anonymus sandbox remove <имя>            # удалить подпесочницу (папка в корзину)
anonymus sandbox remove <имя> --drop-stash   # ... и stash её ветки
```

## Песочница в Docker

Если песочница смонтирована в контейнер (`sandbox.ps1` из transfer tool), правки
агента внутри контейнера попадают на диск Windows, и утилита видит их как обычно.
Если какие-то изменения не замечаются, включите `sync.poll: true`.

## Ограничения

Утилита снижает риск утечки, но не гарантирует полную анонимизацию: таблицу замен
нужно поддерживать, а предупреждения об утечках — проверять. Она не заменяет
разрешения заказчика на работу с кодом.

## Ветки и подпесочницы

Если проект — git-репозиторий, у каждой его ветки может быть своя
**подпесочница**. Так несколько агентов работают параллельно, каждый в своей папке.
Синхронизируется одна активная подпесочница: папка проекта одна, и в ней стоит
ветка активной подпесочницы. Получается аналог `git worktree`, только с
анонимизацией.

В интерфейсе нажмите `b`:

| Клавиша | Действие |
|---|---|
| `Enter` | переключиться на выбранную подпесочницу |
| `n` | новая: ввести имя → создаётся ветка от текущей, папка и подпесочница, утилита переключается на неё и заполняет её |
| `d` | удалить неактивную: папка уходит в `.anonymus/trash`, git-ветка остаётся. Если у ветки есть незакоммиченная работа в stash, утилита спросит: `y` — удалить и stash, `o` — оставить stash |
| `Esc` | назад |

Что происходит при переключении:

1. Синхронизация останавливается, состояние сохраняется.
2. Незакоммиченные изменения текущей ветки убираются в `git stash` с пометкой
   подпесочницы. `anonymus.yaml` и `.anonymus/` в stash не попадают никогда.
3. `git checkout` ветки выбранной подпесочницы. Если у этой ветки был свой stash,
   он возвращается.
4. Скан и сверка. Если изменения односторонние — например, пока подпесочница была
   неактивна, в ней работал агент, — они применяются сами, без экрана выбора.

Где создаются подпесочницы: рядом с основной (`sandbox:`) или в папке
`sandboxes_dir:` из конфига. Имя папки анонимизируется: подпесочница для ветки
`BIGcorpProject-uart` будет лежать в папке `MyProject-uart`, и реальное имя не
попадёт в путь, который видит агент.

Если ветку в проекте переключили вручную, при запуске утилита сама сделает
активной подпесочницу этой ветки. Если такой подпесочницы нет, утилита не
сканирует и не сверяет: иначе файлы чужой ветки попали бы в подпесочницу. Вместо
этого появляется экран выбора:

| Клавиша | Действие |
|---|---|
| `a` | новая подпесочница для текущей ветки: новая ветка не создаётся, папка (с анонимизированным именем) заполняется из проекта |
| `x` | `git checkout` ветки активной подпесочницы |
| `b` | список подпесочниц |
| `q` | выход |

Тот же экран появляется, если после переключения ветка всё равно не та (например,
git отказался делать checkout). В режиме `--no-tui` утилита в этом случае
не запускается и подсказывает, что сделать.

Если ветку переключили, пока синхронизация идёт (`git checkout` в терминале или
в VS Code), утилита не даст содержимому другой ветки попасть в подпесочницу.
Каждую секунду и перед каждым файлом она проверяет `.git/HEAD`, а пока git
держит `.git/index.lock` (checkout ещё идёт), ничего не применяет. Как только
ветка сменилась, синхронизация останавливается, накопленные изменения
отбрасываются: они пришли от checkout, а не от правок. Рамка становится красной:
«ветка сменилась вне anonymus: X → Y». Выбор такой: `s` — перейти на подпесочницу
ветки Y, если она есть; `x` — `git checkout X` обратно; `q` — выход. Пока выбора
нет, ничего не синхронизируется. После `s` или `x` идут обычные скан и сверка.
В режиме `--no-tui` утилита пишет об этом в лог и завершается с кодом 1.

Список подпесочниц хранится в `.anonymus/sandboxes.json`. Без git работает
одна подпесочница `default` — как раньше.

## Слияние работы нескольких агентов

Несколько агентов работают параллельно, каждый в своей подпесочнице. Слить их
работу вместе поручается ещё одному агенту.

1. **В начале работы** создайте ветку-основу и от неё ветки агентов (экран `b`):
   - `n` → `result_merge` → Enter (от `main`, с переключением);
   - `n` → `agent-a` → Enter → **`s`** — создать, не переключаясь. Папка сразу
     заполняется из ветки `result_merge`, и в ней можно запускать агента. Ветку-основу
     при создании можно сменить клавишей `Tab`;
   - то же для `agent-b`, `agent-c`.
2. **Агенты работают.** Синхронизировать их подпесочницы не обязательно: при
   слиянии берётся текущее содержимое их папок.
3. **Подготовить слияние.** На экране `b` встаньте на `result_merge` и нажмите `m`.
   Подпесочницы, созданные от неё, уже отмечены; пробел — изменить выбор, Enter —
   подготовить. В папке `result_merge/.anonymus-merge/` появятся:
   - `agent-a.patch`, `agent-b.patch`, … — что изменил каждый агент относительно
     общей основы, в git-формате и только с плейсхолдерами;
   - `index.txt` — сводка: сколько файлов изменено, добавлено и удалено.

   Эта папка никогда не синхронизируется в проект. Повторное `m` пересоздаёт
   патчи, если агенты продолжили работу.
4. **Агент сливает.** Готовая инструкция для агента, которую можно вставить в
   его `CLAUDE.md`, — [docs/agent-merge.md](docs/agent-merge.md). Скажите агенту в подпесочнице `result_merge`:
   «примени изменения из `.anonymus-merge/*.patch`, разреши пересечения, собери и
   проверь проект». Его правки обычной синхронизацией уходят в проект, на ветку
   `result_merge` (она должна быть активной).
5. **Зафиксировать.** На экране `b` нажмите `k`. Сообщение коммита уже подставлено
   («Слияние: agent-a, agent-b, agent-c»), Enter — закоммитить. Всё слитое ложится
   одним коммитом.
6. **Забрать в `main`** — как обычно: `git checkout main && git merge result_merge`
   или через PR.

Из командной строки:

```powershell
anonymus sandbox new result_merge
anonymus sandbox new agent-a --from result_merge --no-switch
anonymus merge result_merge            # источники по умолчанию — ветки от result_merge
anonymus commit                        # или: anonymus commit -m "сообщение"
```
